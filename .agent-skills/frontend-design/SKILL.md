# Medus Frontend Design

Identify the product, target user, primary job, and existing visual language before designing.

For meaningful redesigns, define a compact design system before coding: core colors and roles, typography hierarchy, spacing/layout logic, one memorable visual idea, mobile behavior, and accessibility constraints.

Avoid generic AI aesthetics: repetitive rounded cards, arbitrary gradients, excessive centered sections, decorative numbering, all-caps micro-labels everywhere, and motion on every component.

Use visual structure to communicate information, not decorate it. Spend boldness in one place and keep supporting UI restrained.

Write interface copy from the user's perspective. Buttons should name the action. Errors should explain what happened and how to recover. Empty states should point to the next useful action.

Production quality floor: responsive mobile layout, visible keyboard focus, adequate contrast, reduced-motion support, clear loading/empty/error/success states, and no obvious CSS specificity conflicts.

Before delivery, critique the result against the brief: if it could plausibly belong to any unrelated SaaS product, revise the generic parts.
